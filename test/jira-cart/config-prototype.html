The Cart Export Bench

This page is for one question: does the ⚙ settings screen work inside a drawer this small? The drawer below is the real thing at real proportions — zoom magnifies it, it never widens it, because a 900px settings panel would answer a question about a UI that cannot ship. Three panel layouts to compare. What the settings emit is folded away at the bottom.

Press ⚙ in the drawer's own head. It is a state button, like jira-ux's padlock: on, it goes blue and the settings are the drawer's whole body — the two sections and the six-button foot are not rendered at all. Off, they come back.

Tabs are the chosen layout, and the open question is how many. Three structures on the switch, built from the same four groups. The one that matters is where Issue reference goes: it governs all three exports, so the three-tab structure lifts it above the tab bar rather than hiding it inside one export's tab. Your last tab is remembered across reloads.

Set Width to 300 min and Height to 215 min to see the panel at the tightest size the drawer can be. That is where a settings screen breaks, and it is why the panel is a screen rather than a strip above the sections.

What this prototype is not

  • Almost no storage. The one exception is the thing you asked to be remembered: which tab you were last on lives in localStorage here, so you can watch it survive a reload. Everything else resets. In the script it is one string in gt-jira-cart.prefs, checked against the known ids exactly as layout and corner already are — an id this build does not recognise falls back to the first tab rather than blanking the screen.
  • Two layouts were prototyped and dropped: one long scroll, and collapsible groups with a remembered open set. Tabs won on use.
  • No fetch. Seven fixed issues — the six A.9 measured against, plus GLX-402, which stands for an issue Jira returns nothing about.
  • No arming ladder. No 📋 Fetching…, no expiry, no per-button held result.
  • The sections and the foot are sketches, there only so you can see what ⚙ replaces. Their real behaviour is not modelled.
  • The drag has no keyboard path, matching §6 item 4: the Cart is not operated by keyboard.
  • Zoom magnifies, it does not widen. Every proportion is the real one at the width shown, which is the only honest way to judge a 300px panel.
